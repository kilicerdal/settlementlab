# V4.2 — controlled obligation lifecycle

Release: `4.2.0`. Portfolio website and deployment remain unchanged.

V4.2 extends the local synthetic USD equity reference system with revision-bound approvals, explicit partial execution, UTC deadlines and independently imported reconciliation evidence. Runtime uses the Python standard library. Local AI remains optional; no hosted-model subscription is required.

## Workflow and invariants

| Command | Identity | Effect | Retained evidence |
| --- | --- | --- | --- |
| Amend | Maker | Complete replacement of unposted terms; returns trade to `RECEIVED` | Original and replacement terms; reason; actor; revision |
| Partial execution | Checker | Explicit positive quantity, bounded by remaining obligation and shared capacity | Four balanced DVP legs, execution slice, cumulative receipt |
| Cancel remainder | Checker | Closes future execution; never reverses posted value | Reason, original executions and approval decisions |
| Import statement | Checker | Compare independently supplied full statement with current cumulative receipts | Original rows, digest, internal snapshot, classified cases |
| Resolve case | Checker | Verify a distinct corrected imported statement against current receipts | Original discrepancy, resolution reason, evidence statement and comparison snapshot |

Amendment increments both the trade version and lifecycle revision. Prior approval decisions remain immutable but do not authorize the replacement revision. Manager submissions are also revision-bound. Active queue jobs and claimed workers are fenced in the amendment/cancellation transaction. New terms must be matched, submitted for review and approved again.

Posted terms cannot be amended. A cancellation after 25 of 100 units executed leaves 25 posted and 75 cancelled. `remaining_quantity` describes unexecuted quantity even when the obligation is closed; inspect `state` before treating it as actionable.

Each lifecycle command requires a current integer `version` and `Idempotency-Key`. Exact replay returns the original committed response; reuse with changed actor or payload returns conflict. Replaying an earlier execution can therefore return its earlier state, rather than the latest trade state. Refresh the snapshot for current state.

Insufficient capacity fails the requested slice without shrinking it. Earlier execution remains posted. Fund synthetic participant capacity, refresh the version, then submit a new reviewed attempt. Funding never changes the accepted economic terms.

## Try locally

```sh
python -m pip install .
settlementlab --db /tmp/lifecycle.db --business-timestamp 2026-11-09T16:30:00Z --model ''
```

Open `http://127.0.0.1:8080/lifecycle`. Create, match and approve shared-ledger trades in the existing trade workbench. The lifecycle screen provides partial execution, amendment, cancellation, revision history, aging, CSV imports and case resolution. Demo personas are freely switchable, not authenticated humans.

`--settlement-cutoff 17:00` pins a project-defined UTC cutoff on new shared-ledger trades. A timed clock enforces the original deadline, including subsequent days; a date-only clock explicitly does not infer time of day. Migrated V4.1 trades keep an empty cutoff rather than gaining a retroactive restriction. This calendar is a simulation policy, not an exchange holiday or jurisdictional settlement calendar. There is no deadline override in this version.

Workers must use the same simulated timestamp as the server:

```sh
settlementlab-worker --db /tmp/lifecycle.db --business-timestamp 2026-11-09T16:30:00Z --once
```

A durable batch entry can include `quantity` alongside `trade_id` and `version`. Omit quantity to execute the full remaining obligation. Partial success produces a successful processing receipt and a versioned observer update, even though the trade is still `PARTIALLY_SETTLED`.

## API additions

- `POST /api/trades/{id}/amend`: `{version, reason, terms}`; `terms` contains symbol, side, currency, quantity, price, trade_date and settlement_date.
- `POST /api/trades/{id}/settle-partial`: `{version, quantity}`.
- `POST /api/trades/{id}/cancel`: `{version, reason}`.
- `POST /api/reconciliation/statements`: `{statement: CSV_STRING_OR_ROW_ARRAY}` with `Idempotency-Key`.
- `GET /api/reconciliation`: retained cases.
- `GET /api/reconciliation/statements/{id}`: original imported rows, digest and internal comparison snapshot.
- `POST /api/reconciliation/cases/{id}/resolve`: `{statement_id, reason}`.

CSV header: `trade_id,quantity,amount_cents`. Values are exact nonnegative integers; duplicate identifiers, ambiguous values and malformed rows are rejected. Limit: 64 KiB CSV / 1,000 rows. Supply a full independent statement: omitted internal receipts become `MISSING_EXTERNAL`; unknown external receipts become `MISSING_INTERNAL`; different quantity/cents become `VALUE_MISMATCH`. Imported evidence is user supplied and cannot prove counterparty authenticity.

The slice oracle reads the database independently and compares actual four-leg postings with externally retained accepted terms and execution totals. It detects balanced but economically incorrect postings. It complements the existing full-execution oracle; neither proves real-market correctness. ## Deliberate limits

One local SQLite database serializes writers. Measurements cover a bounded synthetic workload, not a distributed performance claim. No real counterparties, cash, securities, external feeds or production authentication are connected. Execution and revision history are retained locally; retention/export administration remains future work. Financial state is deterministic; optional AI commentary does not authorize commands or resolve numeric discrepancies.

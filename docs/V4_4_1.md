# V4.4.1 — system SQLite compatibility patch

V4.4.1 packages the compatibility fix merged after V4.4.0. Both wheels use version 4.4.1; the cold-WAL fix applies to the financial workbench, while the independent HTTP assurance wheel remains domain-free.

The reproduced failure was macOS system Python 3.9.6 / SQLite 3.54.0 opening a WAL database without sidecars through a read-only handle. The fix initializes SQLite-owned sidecars only when needed and returns a physically read-only consumer. It does not use immutable mode, a writable investigation connection, a writer transaction or a journal-mode downgrade. Consistent snapshots and concurrent writers remain covered. See [before/after evidence](FRESH_CHECKOUT_V44.md).

Backup finalization also handles the affected build's leftover destination SHM after verified conversion to a standalone DELETE-mode image. Source sidecars are untouched. There is no schema change from V4.4.0; normal online backup guidance still applies.

## Install the downloadable workbench

Download `settlementlab-4.4.1-py3-none-any.whl` and `SHA256SUMS` from [V4.4.1](https://github.com/kilicerdal/settlementlab/releases/tag/v4.4.1), check the hash, then install the exact wheel in a virtual environment:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --no-index ./settlementlab-4.4.1-py3-none-any.whl
.venv/bin/settlementlab-incident --serve --output ./incident-v441
# Open http://127.0.0.1:8086/investigation; stop with Ctrl+C.
```

Choose a fresh output path and a free port 8086. This generates the completed synthetic incident, not an empty workbench. It requires no source checkout, model or paid service. Version metadata must report 4.4.1:

```sh
.venv/bin/python -c 'from importlib.metadata import version; print(version("settlementlab"))'
```

For the independent engine, install `settlementlab_assurance-4.4.1-py3-none-any.whl` instead. It provides `settlementlab-http-assure` and does not install the financial application. See [standalone assurance](STANDALONE_ASSURANCE.md).
